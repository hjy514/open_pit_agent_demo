# 里程碑11：长程连续巡检与自动观察镜头

日期：2026-08-01

## 1. 为什么保留短、长两个正常场景

`normal_inspection` 是快速健康检查，用较短路线验证CARLA连接、能力调度、导航、到达和驻车。`long_patrol` 是可视化展示场景，三辆车各执行两段路线，适合观察、讲解和录屏。

两者分开可以让开发回归保持快速，同时避免比赛展示几秒钟就结束。

## 2. 长程场景

配置文件：

```text
configs/town03_long_patrol.json
```

场景固定包含6项任务：

| 等效装备 | 第一段 | 第二段 |
|---|---:|---:|
| 感知巡检车01 | 出生点136到256 | 256到110 |
| 融合巡检车02 | 出生点122到243 | 243到20 |
| 应急执行车01 | 出生点0到42 | 42到179 |

专属能力标签保证每辆车执行自己的两段路线。Town03到达阈值为10米，用于吸收道路生成点与车辆实际停车点的离散误差；它不是矿山安全距离。

控制场景总上限为16000 tick，运行会在6项任务全部完成后提前结束，不会无条件跑满。

## 3. 自动观察镜头

CARLA观察者相机每个仿真tick读取正在执行的任务，选择优先级最高的车辆，并放置在车辆后上方。当前目标车辆完成任务后，相机会切换到仍在执行的最高优先级车辆。

切换会记录：

```text
spectator_camera_target_changed
```

相机逻辑只负责展示，不参与任务分配、路径规划或车辆控制。换成矿山地图后可以保留选择逻辑，再根据矿用车辆尺寸调整跟随距离、高度和俯角。

## 4. 终态驻车

车辆没有后续任务时施加制动和手刹。全部任务完成后，系统继续推进少量CARLA物理tick，直到所有车辆速度低于0.05 m/s，最多等待120 tick，并记录：

```text
terminal_state_settled
```

该过程使用CARLA真实物理制动，不直接把显示速度改成0。

## 5. 验收结果


结果为 `PASS`，6/6任务完成，完成率100%，执行7704 tick，并产生2次观察镜头目标切换。

驻车收尾回归证据：

```text

```

结果为 `PASS`。系统在25个收尾tick后测得三辆车均低于0.05 m/s，其中感知巡检车为0.000687 m/s。

## 6. 迁移到矿山环境

保留：

- 短健康检查与长展示场景分层；
- 多阶段任务队列和优先级选择；
- 自动观察目标选择；
- 终态驻车实测验收和事件证据。

重新标定或替换：

- 矿区OpenDRIVE/GIS路网及路线；
- 矿用车辆蓝图、轴距、载荷和动力学；
- 相机跟随距离、高度和俯角；
- 到达半径、制动时间、停车距离和坡道防溜车阈值；
- 真实矿区交通规则与安全规范。

因此本里程碑证明的是Town03城镇道路代理环境下的可视化与控制闭环，不代表矿山工业安全性能已经得到验证。
