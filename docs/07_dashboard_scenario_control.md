# 里程碑07：可视化场景控制

日期：2026-08-01

## 1. 本阶段目标

将原来的命令行启动流程接入浏览器：

```text
网页选择白名单场景
        ↓
本机控制接口校验
        ↓
重新加载Town03并启动run_demo.py
        ↓
生成实时事件和证据
        ↓
页面自动跟随新运行
```

## 2. 可启动场景

| 场景ID | 页面名称 | 核心验证 |
|---|---|---|
| `competition_demo` | 比赛一键综合演示（推荐） | 故障、风险、管控、应急和工单完整闭环 |
| `normal_inspection` | 正常三车巡检 | 能力分工、导航、到达 |
| `long_patrol` | 长程连续巡检（推荐观察） | 三车两段路线、镜头切换、终态驻车 |
| `fault_recovery` | 故障抢占与恢复 | 故障注入、接管、恢复 |
| `orange_risk` | 橙色风险复核 | 风险评估、融合巡检、工单 |
| `red_response` | 红色风险多装备联动 | 道路管控、应急响应、多工单 |

每个场景固定绑定项目配置、风险配置、tick上限和是否注入故障。

## 3. 安全边界

控制接口不接受：

- 任意可执行文件；
- 任意shell命令；
- 用户提供的配置路径；
- 用户提供的风险文件路径；
- 同时运行多个Demo。

后台使用参数列表直接启动Python，不经过shell。控制服务强制监听 `127.0.0.1`、`localhost` 或 `::1`。

页面启动前明确提示：`--load-map` 会重新加载Town03并清除当前CARLA世界中的车辆和状态。

停止时先向Demo发送 `SIGINT`，使CARLA适配器执行清理并释放 `BasicAgent`，不直接强制杀死进程。

## 4. 控制状态

接口：

```text
GET  /api/control/scenarios
GET  /api/control/status
POST /api/control/start
POST /api/control/stop
```

控制状态包括：

- `idle`、`running`、`stopping`、`finished`；
- 当前场景ID；
- 进程PID；
- 启动时间；
- 退出码；
- 控制日志路径和日志尾部。

运行过程中页面禁用再次启动，只开放安全停止。新证据目录出现后，页面自动切换到最新运行。

## 5. 端到端验收

通过控制接口启动：

```json
{"scenario_id": "normal_inspection"}
```

控制日志：

```text
artifacts/control/20260801T075839Z-normal_inspection.log
```

运行证据：

```text
artifacts/runs/town03-feasibility-v1-20260801T075839Z-33239927
```

结果：

| 指标 | 结果 |
|---|---:|
| 控制进程退出码 | 0 |
| 运行状态 | PASS |
| 任务完成 | 3/3 |
| 完成率 | 100% |
| 自动结束 | tick 413 |

这证明页面控制、CARLA运行、证据生成和可视化状态读取形成完整闭环。

## 6. 对矿山迁移的影响

控制器本身可保留。迁移矿山环境时新增一个经过审核的矿山场景定义，固定绑定：

- 矿山地图；
- 矿用装备配置；
- 真实或回放数据源；
- 矿区验收tick和安全规则。

不能把矿山场景做成任意配置上传后直接执行；比赛Demo和实际系统都应保持场景审核、权限控制和操作审计。
