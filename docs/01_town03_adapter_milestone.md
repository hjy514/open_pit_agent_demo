# 里程碑 01：Town03 三车调度与故障抢占

> 本文是里程碑 01 的历史记录。任务到达验收、队列恢复和完整故障接管结果见 `docs/02_task_lifecycle_and_fault_recovery.md`。

日期：2026-08-01

## 1. 本阶段定位

本阶段使用 CARLA 自带 `Town03` 和三辆普通汽车，进行第三方调度平台的功能级可行性验证。

它验证的是通用软件接口和控制闭环，不是露天矿场景验证、矿用装备性能验证或工业性试验。

## 2. 为什么先做 Town03

- 排除自制矿山地图、矿用车辆资产和岩土模型带来的额外变量；
- 优先打通“第三方程序—CARLA—车辆状态—目标点—车辆控制”链路；
- 让后续矿山迁移主要表现为配置和适配器变化，而不是推倒重写；
- 尽早产生可重复运行的日志和测试结果。

## 3. 与最终赛题目标的对应关系

| 当前验证内容 | 对应最终目标 | 当前结论边界 |
|---|---|---|
| 三辆车辆使用稳定业务 ID 和不同能力标签 | 异构具身装备协同 | 仅为普通车辆等效角色 |
| 能力、距离、优先级和负载约束的任务分配 | AI Agent 上层调度工具 | 当前为确定性基线调度器 |
| 车辆故障后停止并释放任务 | 集群容错重构 | 当前为软件故障注入 |
| 高优先级任务抢占低优先级任务 | 风险事件驱动的动态调度 | 尚未接入真实边坡风险事件 |
| 调度器输出目标，BasicAgent 负责车辆控制 | 调度、路径规划、底层控制分层 | BasicAgent 不是最终矿山驾驶算法 |
| JSONL 事件和 JSON 摘要 | 工单、审计和测试证据基础 | 尚未形成完整工单状态机 |

## 4. 已完成的现场测试

### 4.1 CARLA 连接与车辆识别

- 成功连接 `127.0.0.1:2000`；
- 确认当前地图为 `Town03`；
- 通过 `role_name` 识别三辆项目车辆；
- 每辆车输出业务 ID、actor ID、位置、速度、能力和健康状态。

### 4.2 自适应出生点

初始配置的第 1、2 号出生点存在占用/碰撞，适配器改为：

1. 优先尝试配置的出生点；
2. 失败后搜索其他安全出生点；
3. 新车生成后等待一个 CARLA 世界帧；
4. 再读取位置并规划路线。

该策略可以适配后续矿山地图中不同数量和布局的出生点。

### 4.3 正常目标下发

三辆车分别接收三个虚拟巡检区目标。运行 120 帧后，三辆车均产生非零速度，证明任务分配、BasicAgent 路径生成和车辆控制链路有效。


### 4.4 控制器生命周期修复

CARLA 0.9.10 的 `LocalPlanner.__del__()` 默认会销毁车辆。初次运行结束后，三辆车被意外删除。

第三方适配器现会在释放控制器前调用 `reset_vehicle()`，解除规划器对车辆生命周期的所有权。修复后：

- 控制进程退出；
- 三辆车保留在 CARLA 世界；
- 新进程能再次通过原 actor ID 发现车辆。

修复后短测证据：

```text

artifacts/runs/town03-feasibility-v1-20260801T055137Z-349d1e25
```

### 4.5 故障重分配和高优先级抢占

最终现场测试：

- 第 80 帧注入 `inspection_vehicle_01` 故障；
- 故障车的 2 号区域任务被释放；
- 调度器将其分配给具备相机能力的 `inspection_vehicle_02`；
- 2 号区域优先级 100，高于巡检车02当前3号区域任务的优先级50；
- 巡检车02安全释放原控制器，立即切换到2号区域任务；
- 原3号区域任务保留为已分配状态，等待后续继续；
- 故障车最终速度为0，状态为 `available=false`、`health=fault`。

## 6. 当前不能声称完成的内容

- 尚未使用露天矿地图或矿用装备；
- 尚未接入固定监测站和移动巡检监测数据；
- 尚未建立边坡蓝、黄、橙、红风险模型；
- 尚未实现风险区域禁行和替代路径规划；
- 尚未实现应急工单完整状态机；
- 尚未接入真实大语言模型或 MFS-LLM；
- 尚未验证任务最终到达率、长时间运行稳定性和严格响应时间；
- 当前 CARLA 使用异步模式，正式计时测试前需建立同步仿真和固定随机种子；
- 故障和任务状态当前主要保存在运行进程内，服务重启后的业务状态恢复尚未实现；
- 当前测试结果不能替代典型矿山数据验证、工业性试验或样机测试。

## 7. 下一里程碑建议

下一阶段接入边坡风险最小闭环：

1. 定义固定站读数、移动巡检读数和 `RiskEvent` 数据结构；
2. 用明确标注的合成时序数据模拟正常、缓慢变形、加速变形和临滑阶段；
3. 建立透明可解释的蓝、黄、橙、红规则基线；
4. 橙色风险生成高优先级复核任务；
5. 复用本阶段的抢占机制，暂停普通巡检并调度复核装备；
6. 保存风险曲线、触发原因、响应时间和任务变化证据；
7. 再接入禁行路段和应急工单状态机。
