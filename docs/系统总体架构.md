# 系统总体架构

## 系统定位

系统由 CARLA 数字矿山、Agent 后端、静态地图资源库、运行数据库和 PyQt6 调度中心组成。CARLA 是高保真执行与验证环境，不是调度策略本身；PyQt 负责展示和人工操作，不承载核心调度逻辑。

```text
Scenario Catalog / Concrete Episode
                ↓
World State → Hard Constraints → Feasible Candidates
                ↓
        Scheduling Policy → Route Planner → Safety Shield
                ↓
             CARLA / Mock Execution
                ↓
             Feedback → openpit.db → Dataset / Evaluation
```

## 核心模块

| 层 | 当前模块 | 职责 |
|---|---|---|
| Scenario | `scenario/` | 场景生命周期、事件、随机任务、资源准入和统一运行入口 |
| State / Risk | `runtime_state.py`、`monitoring.py`、`risk.py` | 运行状态、监测、风险和道路状态 |
| Decision | `scheduler.py`、`decision/` | Heuristic V0、多目标 V1、安全审查与候选解释 |
| Planning / Execution | `map_resources/road_graph.py`、`adapters/`、`scenario/carla_execution.py` | 路线事实、CARLA 控制和执行反馈 |
| Data | `sqlite_store.py`、`evidence.py`、`decision_intelligence.py` | 运行记录、证据、指标和训练数据基础 |
| Application | `interfaces/api_server.py`、`open_pit_dispatch_app/` | API、PyQt 展示和人工命令 |

## 两类闭环

实时执行闭环：

```text
状态 → 风险/事件 → 决策 → 路线 → 安全审查 → CARLA执行 → 反馈 → 新状态
```

学习优化闭环：

```text
已验证运行 → openpit.db / Dataset → 策略评估 → 新策略候选 → 固定Seed比较 → CARLA验证
```

当前项目已实现前者的基础闭环和后者的数据记录接口；行为克隆、PPO、MARL 不属于当前正式运行策略。

## 唯一事实来源

| 事实 | 唯一来源 |
|---|---|
| 静态出生点、道路、可达性、物理路线验证 | `map_resources.db` |
| 某次 Episode、事件、决策、任务与反馈 | `openpit.db` |
| 场景逻辑定义 | 迁移目标：`configs/scenario_catalog.json` |
| 当前演示配置 | S08：`mine_competition_demo.json`；其他场景配置正在兼容迁移 |
| 代码历史 | Git 提交、Tag、Branch |

## S08 保护原则

`start_slope_demo.sh`、`run_demo.py` 和边坡相关配置是比赛 Golden Demo。场景框架、数据库和 API 的重构只能以兼容层接入，不得重写或改变它已验证的业务行为。
