# 环境配置与部署说明

更新时间：2026-09-11  
适用版本：OpenPit-Agent 当前比赛提交版

本文用于在另一台 Linux 演示机上复现项目。项目由 Agent 后端、PyQt6 调度中心和 CARLA 物理执行环境组成，三个部分可以使用不同的 Python 环境。

## 一、运行环境清单

| 组件 | 当前验证配置 | 用途 |
|---|---|---|
| 操作系统 | Linux x86_64 | 项目脚本和 CARLA 运行环境 |
| Agent Python | Python 3.7.15（`openpit-agent`） | Agent、场景、调度、数据库和 CARLA Python API |
| 调度中心 Python | Python 3.10.20（`openpit-ui`） | PyQt6 调度界面 |
| CARLA | 0.9.10 | 数字矿山和车辆物理执行 |
| 地图 | `0325_5` | 露天矿道路、出生点和路网拓扑 |
| 矿卡蓝图 | `vehicle.cat.cat` | CARLA 中的矿卡模型 |
| Agent API | FastAPI 0.95.2 + Uvicorn 0.22.0 | 本机 `127.0.0.1:8000` |
| 调度中心 | PyQt6 6.9.1 + requests 2.33.1 | 人机协同调度和运行展示 |

CARLA 需要可用的图形显示和足够的 GPU/显存资源。正式演示使用默认启动参数，不额外添加低画质、离屏或无渲染参数；若出现显存不足，应先关闭其他图形程序并重新启动 CARLA。

## 二、提交包需要准备的内容

代码仓库应包含：

- `src/`、`open_pit_dispatch_app/`、`scripts/`、`configs/`、`tests/`；
- `requirements.txt` 和 `open_pit_dispatch_app/requirements.txt`；
- `start_carla.sh`、`start_api.sh`、`start_dispatch_app.sh`、`run_scenario.sh`、`check_environment.sh`；
- `data/database/map_resources.db`（地图资源库）和一份可选的 `openpit.db` 示例库；
- CARLA 0.9.10 运行包、`0325_5` 地图包以及包含 `vehicle.cat.cat` 的内容包。

数据库和 CARLA 大文件通常不放入 Git，应与代码包分开提交，并在交付目录中保持下面的相对结构：

```text
open_pit_agent_demo/
├── src/
├── configs/
├── scripts/
├── data/database/
│   ├── map_resources.db
│   └── openpit.db
└── docs/
```

## 三、首次配置

### 1. Agent 后端环境

建议使用已有的 `openpit-agent` 环境；如需重新创建，使用 Python 3.7，并安装仓库根目录依赖：

```bash
conda create -n openpit-agent python=3.7
conda activate openpit-agent
python -m pip install -r requirements.txt
```

CARLA 0.9.10 的 Python egg 必须来自交付的 CARLA 包，不能混用其他 CARLA 版本。启动脚本会优先自动寻找：

```text
~/miniconda3/envs/openpit-agent/bin/python
```

### 2. 调度中心环境

建议使用已有的 `openpit-ui` 环境；调度中心依赖安装方式如下：

```bash
conda create -n openpit-ui python=3.10
conda activate openpit-ui
python -m pip install -r open_pit_dispatch_app/requirements.txt
```

启动脚本会优先自动寻找：

```text
~/miniconda3/envs/openpit-ui/bin/python
```

### 3. CARLA 路径

日常运行不需要手动设置环境变量。脚本会自动寻找常用的 CARLA 安装位置。跨电脑路径不同且无法自动识别时，再设置：

```bash
export OPENPIT_CARLA_ROOT=/实际路径/LinuxNoEditor
```

同理，只有自动识别失败时才需要设置 `OPENPIT_PYTHON` 或 `OPENPIT_DISPATCH_PYTHON`。

## 四、启动顺序

在项目根目录打开三个终端，依次执行：

```bash
./start_carla.sh
```

确认 CARLA 已启动并加载 `0325_5` 后：

```bash
./start_api.sh
```

再启动调度中心：

```bash
./start_dispatch_app.sh
```

调度中心启动后选择 S01、S02、S04、S09 或 S08，设置车辆数和 Seed，再启动场景。命令行入口 `run_scenario.sh` 保留用于验收、排障和批量运行。

## 五、启动前检查

```bash
./check_environment.sh --require-target-map --check-api --check-ui
```

检查通过应至少包含：目标地图 `0325_5`、CARLA 版本 `0.9.10`、出生点/路网可读取、矿卡蓝图 `vehicle.cat.cat`、`openpit.db` 和 `map_resources.db` 可读取。

代码包本身可进行离线检查：

```bash
python -m unittest discover -s tests -q
python -m compileall -q src scripts open_pit_dispatch_app
```

## 六、常见问题

1. **找不到 CARLA**：确认 `CarlaUE4.sh` 存在，或设置 `OPENPIT_CARLA_ROOT`。
2. **当前地图是 Town03**：先启动 CARLA，再通过调度中心加载 `0325_5`，或按项目运行说明执行地图加载命令。
3. **找不到 `vehicle.cat.cat`**：检查交付的 CARLA 内容包是否已安装，并确认 CARLA 版本为 0.9.10。
4. **数据库为空**：首次运行可由程序创建 `openpit.db`；多车路线和地图准入需要随包提供已生成的 `map_resources.db`。
5. **调度中心无法启动**：确认使用 `openpit-ui` 环境，并检查 PyQt6 和 requests 是否安装。
6. **CARLA 显存不足**：关闭其他图形程序，保持默认启动方式重新启动，必要时降低同时运行的场景规模。

## 七、交付口径

代码仓库负责提供可复现的程序结构、配置和启动入口；CARLA 运行包、地图、矿卡模型、数据库和代表性运行证据作为配套运行材料提供。这样既便于 Git 管理，也便于企业或评审环境按清单部署。
