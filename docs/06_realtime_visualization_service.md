# 里程碑06：实时数据服务与可视化态势台

日期：2026-08-01

## 1. 本阶段目标

将命令行和 JSON 证据转换为浏览器可理解的实时状态：

```text
CARLA / Mock / 调度器
          ↓
     结构化事件日志
          ↓
      实时状态投影
          ↓
  HTTP接口 + 浏览器态势台
```

数据服务不改变调度、风险和工单逻辑。以后换成矿山地图，界面继续使用统一接口。

## 2. 为什么使用事件投影

每次运行已经持续写入 `events.jsonl`。可视化服务读取完整事件链，推导当前车辆、任务、风险、限制和工单状态，具有三个优点：

- 不需要让 CARLA 控制进程同时承担网页服务；
- 正在运行时可实时读取，运行结束后可回看同一证据；
- 界面展示的内容与比赛留证来自同一事件源。

工单状态变化事件现在包含 `work_order_id` 和 `task_id`，可以将状态变化可靠关联到具体工单。

## 3. 当前接口

| 接口 | 作用 |
|---|---|
| `GET /api/health` | 服务健康检查 |
| `GET /api/runs` | 历史和正在运行的场景 |
| `GET /api/state` | 界面统一状态快照 |
| `GET /api/events` | 原始审计事件 |

`run_id` 必须来自数据目录中的真实运行，服务拒绝未知ID和路径穿越。

## 4. 当前页面

页面包括：

- 场景和运行终态；
- 当前tick、任务完成率、风险等级、工单关闭率和限制数量；
- 三辆代理装备的位置、速度、健康状态和当前任务；
- 蓝、黄、橙、红风险状态及触发原因；
- 任务队列；
- 风险工单；
- 最新事件流；
- 合成数据和未实现真实路段绕行的能力边界。

车辆分布当前是根据 CARLA 世界坐标自动缩放的二维代理视图，不是 Town03 或矿区道路底图。
